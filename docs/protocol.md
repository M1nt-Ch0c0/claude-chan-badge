# 徽章和 Mac 之间的帧格式

一条 TCP 长连接，徽章主动连 Mac 的 19731 端口。小端，每帧 10 字节头：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| magic | u16 | `0xC3A1` |
| type | u8 | 见下表 |
| flags | u8 | 0 |
| seq | u32 | 两个方向各自从 1 开始数 |
| nbytes | u16 | 载荷长度 |

徽章那边整帧要放进 4 KB 的接收缓冲，所以单帧载荷不要超过 4086 字节。

## 帧类型

| type | 方向 | 载荷 |
| --- | --- | --- |
| `0x01` HELLO | 徽章 → Mac | 采样率 u32、声道 u8、能力 u8（bit0：能收字幕位图）。老固件只有前 5 字节 |
| `0x02` HELLO_ACK | Mac → 徽章 | 空 |
| `0x10` PCM | 双向 | 640 字节，16 kHz / 16 bit / 单声道，20 ms |
| `0x11` CTRL | 徽章 → Mac | 1 字节：0 继续，1 暂停 |
| `0x11` CTRL | Mac → 徽章 | `0xA0` + 阶段（0 空闲，1 在听，2 在想，3 在说）；`0xA1` + 0/1（Mac 上点了继续/暂停） |
| `0x12` TEXT | Mac → 徽章 | 角色 u8 + UTF-8 正文。老的字幕通路，固件不支持位图时才发 |
| `0x13` SUBIMG | Mac → 徽章 | 字幕位图，见下面 |

角色：0 清空，1 主人说的，2 小克说的，3 后台任务进度。

## 字幕位图

Mac 用 CoreText 排版，渲染成 4 位灰度（一字节两个像素，高 4 位在左），只发和上一次相比变了的那几行：

| 偏移 | 类型 | 说明 |
| --- | --- | --- |
| 0 | u8 | 角色 |
| 1 | u8 | bit0 = 这次更新的最后一块，徽章收到后才换图 |
| 2 | u8 | 宽（现在固定 200） |
| 3 | u8 | 高（按行数变，最多 3 行，约 66） |
| 4 | u8 | 这块从第几行开始 |
| 5 | u8 | 这块有几行 |
| 6… | | 像素 |

一块最多 28 行。徽章在接收任务里写一块缓冲，界面线程用序号锁去读（写的时候序号是奇数），展开成 A8 交给 LVGL，用 `image_recolor` 上色。说话时字幕大约每秒更新 4 次，实测平均 30～40 kbps，音频本身是 256 kbps。

为什么不发文字让徽章自己排：徽章上 TinyTTF 的字形缓存会随着出现过的字越来越多，开着 Wi-Fi 的时候，它曾经把剩余内存挤到只剩一两 KB。位图的大小是固定的，而且 Mac 想用什么字体、显示什么语言都行。

## 时序

- 徽章麦克风一直按 20 ms 一帧发。暂停时照样读 I2S（免得缓冲堆满），但不发出去。
- Mac 把模型的声音按实时速度发给徽章，只提前 160 ms，每 40 ms 一次把两帧拼成一个 TCP 包。所以 Mac 知道徽章大概念到哪儿了，字幕跟着这个进度一个字一个字地出。
- 她说话时、以及说完后的 0.4 秒内，Mac 丢掉麦克风的帧。喇叭就贴着麦克风，这不是回声消除，所以也不能在她说话时插嘴。
- 阶段 0（空闲）是在徽章真正念完以后才发的，不是模型生成完就发。
